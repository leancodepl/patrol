## Issues encountered and fixes

### 1. Runner crashed on a passing test (`type_error.302`)

**Symptom:** after the first test passed, `patrol_windows_runner` aborted with
`Fatal: [json.exception.type_error.302] type must be string, but is null`.

**Cause:** `PatrolAppServiceClient::RunDartTest` read the `/runDartTest`
response with `body.value("details", std::string{})`. nlohmann's `value()`
only uses the default when the key is *missing*. A key that is present
with `null` (what a passing test sends for `details`) throws. Runs where every
test failed never hit this, because failures send a string.

**Fix:** `packages/patrol/windows_runner/src/patrol_app_service_client.cpp`
now reads `result` and `details` only when they are strings, and treats
anything else as an empty string.

### 2. Explorer demo couldn't find its file

**Symptom:** `No UI element found (name="patrol_explorer_target.txt") within
timeout`. Explorer had opened the right folder.

**Cause:** with "Hide extensions for known file types" turned on (the Windows
default, `HideFileExt=1`), Explorer exposes `patrol_explorer_target.txt` to UI
Automation under the name `patrol_explorer_target`. A UIA probe on this
machine confirmed it. `WindowsSelector.name` matches exactly, so the test
failed on any machine with default settings.

**Fix:** `app/patrol_test/explorer_demo_test.dart` now uses a file with no
extension (`patrol_explorer_target`). Its UIA name is the same whether or not
extensions are hidden.

**Follow-up idea:** a name-contains or regex match on `WindowsSelector` would
make cases like this easier to write.

### 3. Single-file runs ran the whole suite

**Symptom:** `patrol test -d windows patrol_test/explorer_demo_test.dart` also
ran `demo_test.dart`, which failed without the fixture, so the command exited 1.

**Cause:** this is a docs issue, not a Windows issue. `patrol test` on every
platform takes test files through `-t` / `--target`. A file passed without the
flag is silently ignored, and with no target the CLI bundles every test.

**Fix:** added `-t` to the commands in `AGENT_RUN.md` and `README.md`.

**Follow-up idea:** the CLI could warn or fail when it gets a file without `-t`.
That would change behaviour on every platform, so it is left for a separate
change.
