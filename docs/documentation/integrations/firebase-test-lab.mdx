title: Firebase Test Lab

There are many device lab providers. Below we're showing how to run Patrol tests
on [Firebase Test Lab], because it's popular in the Flutter community, but the
instructions should be similar for other device farms, such as [AWS Device
Farm][aws_device_farm].

<Info>
  Before you proceed with the steps listed below, make sure that you've
  completed the [native setup] guide.
</Info>

<Tabs
  defaultIndex={0}
  items={['Android', 'iOS']}
>
  <Tab value="Android">
    To run the integration tests on Android, you need 2 apps: the app itself
    (often called the "app under test") and the test intrumentation app.

    To build these apps, run:

    ```
    patrol build android --target patrol_test/example_test.dart
    ```

    The command prints the two APK paths. For an unflavored debug build they are:

    ```
    build/app/outputs/apk/debug/app-debug.apk
    build/patrolTest/outputs/apk/debug/patrolTest-debug.apk
    ```

    Once you have built the apks, use the [gcloud] tool to run them on Firebase
    Test Lab:

    ```
    gcloud firebase test android run \
        --type instrumentation \
        --use-orchestrator \
        --app build/app/outputs/apk/debug/app-debug.apk \
        --test build/patrolTest/outputs/apk/debug/patrolTest-debug.apk \
        --timeout 1m \
        --device model=MediumPhone.arm,version=34,locale=en,orientation=portrait \
        --record-video
    ```

    <Info>
      You must [install the gcloud tool] first. [Here][gcloud_android] you can learn
      more about all available options and flags.
    </Info>

    The test APK already contains the app under test's application ID and, if you
    set `clearPackageData` in `:patrolTest`, the per-test app wipe. No
    `--environment-variables` are required.

    <Info>
      To collect Patrol's native failure screenshots (set `screenshot_on_failure: true`
      in your `pubspec.yaml`), add `--directories-to-pull=/sdcard/Download/screenshots`
      to the command above. You don't need to download them — Firebase Test Lab shows
      them directly in the **Screenshots** tab of the matrix in the console. They're
      also copied into the results bucket at
      `.../<device-model>/artifacts/sdcard/Download/screenshots/<class>/<method>/<timestamp>_failure.png`.
      The PNGs remain available in shared storage across per-test app data clears.
    </Info>

    It's convenient to create a shell script to avoid typing that long command
    every time. You might want to take a look at Patrol example app's
    [run_android_testlab script][example_android_script].

    <Info>
      On Android, all permissions are granted by default. This behavior can be
      changed using the [alpha version of the gcloud tool].
    </Info>

  </Tab>
  <Tab value="iOS">

    To run the integration tests on iOS, you need 2 apps: the app itself
    (often called the "app under test") and the test intrumentation app.

    First, build your Flutter app, choosing the integration test file as target:

    For simulations:
    ```
    patrol build ios --target patrol_test/example_test.dart --debug --simulator
    ```

    For physical devices:
    ```
    patrol build ios --target patrol_test/example_test.dart --release
    ```

    `patrol build ios` outputs paths to the built app binaries, for example:

    ```
    $ patrol build ios -t patrol_test/example_test.dart --release
    • Building app with entrypoint example_test.dart for iOS device (release)...
    ✓ Completed building app with entrypoint example_test.dart for iOS device (31.5s)
    build/ios_integ/Build/Products/Release-iphoneos/Runner.app (app under test)
    build/ios_integ/Build/Products/Release-iphoneos/RunnerUITests-Runner.app (test instrumentation app)
    build/ios_integ/Build/Products/Runner_iphoneos16.2-arm64.xctestrun (xctestrun file)
    ```

    Firebase Test Lab requires these files to be packaged together in a zip
    archive. To create the archive:

    ```
    pushd build/ios_integ/Build/Products
    zip -r ios_tests.zip Release-iphoneos Runner_iphoneos16.2-arm64.xctestrun
    popd
    ```

    Finally, upload the `ios_tests.zip` to Firebase Test Lab for execution:

    ```
    gcloud firebase test ios run \
      --test build/ios_integ/Build/Products/ios_tests.zip \
      --device model=iphone8,version=16.2,locale=en_US,orientation=portrait
    ```

    <Info>
      You must [install the gcloud tool] first. [Here][gcloud_ios] you can learn
      more about all available options and flags.
    </Info>

    If your `.xctestrun` file has different iOS version in its name than the
    device you're running on, simply rename the `.xctestrun` so that the version
    matches.

    It's convenient to create a shell script to avoid typing that long command
    every time. You might want to take a look at Patrol example app's
    [run_ios_testlab script][example_ios_script].

  </Tab>
</Tabs>

## Dart code coverage (Android)

Patrol can collect Dart line coverage on Firebase Test Lab the same way it does
on [BrowserStack][bs coverage]: the app embeds it into the JaCoCo `.ec` files the
test run writes, and `patrol coverage pull` turns them into a `patrol_lcov.info`.

<Steps>
  <Step>
    Instrument the app under test. In **android/app/build.gradle.kts** set
    `enableAndroidTestCoverage = true` (AGP 8+; `testCoverageEnabled = true` on
    AGP 7) on the debug build type. For API levels below 29, also declare
    `WRITE_EXTERNAL_STORAGE` in a debug-only manifest, as in the
    [emulator.wtf guide][ew coverage].
  </Step>
  <Step>
    Build with the coverage dart-defines:

    ```bash
    patrol build android --dart-define=PATROL_BS_COVERAGE=true --dart-define='PATROL_BS_COVERAGE_PACKAGES=^package:my_app/'
    ```

    `PATROL_BS_COVERAGE_PACKAGES` and `PATROL_BS_COVERAGE_FORCE_COMPILE` work
    as described in the [BrowserStack guide][bs coverage].
  </Step>
  <Step>
    Run with coverage, keep package data between tests, and pull the coverage
    directory into the results bucket:

    ```bash
    gcloud firebase test android run \
      --type instrumentation \
      --app build/app/outputs/apk/debug/app-debug.apk \
      --test build/app/outputs/apk/androidTest/debug/app-debug-androidTest.apk \
      --device model=MediumPhone.arm,version=34,locale=en,orientation=portrait \
      --use-orchestrator \
      --environment-variables clearPackageData=false,coverage=true,coverageFilePath=/sdcard/Download/ \
      --directories-to-pull=/sdcard/Download \
      --results-bucket=<bucket> \
      --results-dir=<results-dir>
    ```

    With the orchestrator, `coverageFilePath` (ending with `/`) gives one `.ec`
    file per test. Without it, pass `coverageFile=/sdcard/Download/coverage.ec`
    instead.
  </Step>
  <Step>
    Download the coverage files and merge them:

    ```bash
    gcloud storage cp -r "gs://<bucket>/<results-dir>/<device>/artifacts" .
    ```

    ```bash
    patrol coverage pull --input artifacts --output coverage
    ```

    This writes `coverage/jacoco.exec` (Java/Kotlin) and
    `coverage/patrol_lcov.info` (Dart, merged across all tests).
  </Step>
</Steps>
